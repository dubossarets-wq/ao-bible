# AO Bible в Google Play — что сделать по шагам

Файл приложения: `E:\android-build\out\aobible-1.0-30423986.aab` — самостоятельное приложение (Capacitor): интерфейс внутри, модули скачиваются с aobible.app.
Идентификатор: `app.aobible` (поменять после первой загрузки нельзя).
Ключ загрузки: `E:\android-build\keys\` — сохраните эту папку в двух надёжных местах.

## Шаг 1. DNS в Cloudflare (5 минут)

Cloudflare → домен **aobible.app** → **DNS** → **Records** → **Add record**.
У каждой записи **Proxy status: DNS only** (серое облако, не оранжевое) — иначе GitHub не выдаст сертификат HTTPS.

| Type | Name | Content |
|---|---|---|
| A | `@` | `185.199.108.153` |
| A | `@` | `185.199.109.153` |
| A | `@` | `185.199.110.153` |
| A | `@` | `185.199.111.153` |
| AAAA | `@` | `2606:50c0:8000::153` |
| AAAA | `@` | `2606:50c0:8001::153` |
| AAAA | `@` | `2606:50c0:8002::153` |
| AAAA | `@` | `2606:50c0:8003::153` |
| CNAME | `www` | `dubossarets-wq.github.io` |

Если Cloudflare сам создал другие записи для `@` или `www` (например, парковку) — удалите их.

Ещё в Cloudflare: **SSL/TLS → Edge Certificates → Always Use HTTPS** можно не трогать (облако серое, трафик идёт мимо Cloudflare).

После этого напишите мне — я проверю, что сайт открывается на https://aobible.app, и включу обязательный HTTPS.

**Защита домена (по желанию, рекомендуется):** GitHub → ваш профиль → **Settings → Pages → Add a verified domain** → `aobible.app`. GitHub покажет запись TXT — добавьте её в Cloudflare так же (Type TXT, Name и Content — как показал GitHub), затем нажмите **Verify**. Так никто другой не сможет привязать ваш домен к своему GitHub.

## Шаг 2. Создать приложение в Play Console

1. https://play.google.com/console → **Создать приложение**.
2. Название: `AO Bible — Библия и Стронг`. Язык по умолчанию: **русский**. Приложение (не игра). **Бесплатное**.
3. Отметить согласия → **Создать**.

## Шаг 3. Заполнить разделы «Настройка приложения» (Dashboard)

Ответы — в `listing.md` рядом:
- Доступ к приложению → «Всё доступно без ограничений».
- Реклама → «Нет».
- Возрастной рейтинг → анкета (раздел «Анкета возрастного рейтинга»).
- Целевая аудитория → 13+.
- Новостное приложение → нет.
- Безопасность данных → «Не собирает данные» (раздел «Безопасность данных»).
- Политика конфиденциальности → `https://aobible.app/privacy.html` (когда домен заработает; до этого — `https://dubossarets-wq.github.io/ao-bible/privacy.html`).
- Госприложения, финансы, здоровье → нет.
- Категория → Книги и справочники; контакты → ваша почта.
- Страница в магазине → названия и описания из `listing.md`, значок `icon-512.png`, баннер `feature-1024x500.png`, скриншоты из `screens/` (по номерам).

## Шаг 4. Закрытое тестирование (обязательно, 14 дней)

1. **Тестирование → Закрытое тестирование → Создать трек** (или «Alpha»).
2. **Тестировщики** → создать список адресов, внести **12+ Google-аккаунтов**.
3. **Создать выпуск** → Play App Signing: согласиться (Google хранит ключ приложения, мы подписываем ключом загрузки) → загрузить `aobible-1.0-30423986.aab`.
4. Название выпуска: `1.0.0`. Что нового: «Первая версия».
5. **Отправить на проверку**. Проверка обычно от нескольких часов до нескольких дней.
6. Когда одобрят — скопируйте ссылку «Стать тестировщиком» и разошлите. Каждый должен поставить приложение и не удалять его 14 дней.

## Шаг 5. Отпечаток ключа Google (по желанию)

Приложение самостоятельное (Capacitor), адресной строки в нём нет — этот шаг не обязателен. Он нужен, только если позже захотим, чтобы ссылки aobible.app открывались сразу в приложении: **Тестирование и выпуск → Настройка → Подпись приложений** → «Сертификат ключа подписи приложения» → **SHA-256** — прислать мне.

## Шаг 6. Через 14 дней

Play Console → **Панель → Подать заявку на рабочий доступ** → ответить на вопросы о тестировании → после одобрения выпустить в **Рабочую версию** (Production).

## Как выходят обновления

- Интерфейс лежит внутри приложения, поэтому новая версия = новая сборка в Play: в папке проекта `node scripts/build-android.mjs 1.1` → файл `E:\android-build\out\aobible-1.1-<номер>.aab` → Play Console → новый выпуск → загрузить → на проверку. Номер версии (versionCode) растёт сам: 30 000 000 + минуты с 1.1.2026.
- Модули (переводы, словари, записи) приложение скачивает с aobible.app: новые модули и исправления в них приходят без новой сборки — достаточно выкладки «в прод».
- Сайт (старый адрес и aobible.app) обновляется как раньше: `npm run deploy`.

## Как выпускать исправления (чтобы не попало ко всем сразу)

1. Исправление проверяется на тестовом сайте (код у сайта и приложения общий).
2. Сборка: `node scripts/build-android.mjs 1.0` → `E:\android-build\out\aobible-1.0-<номер>.aab`.
3. Play Console → **Внутреннее тестирование** → «Создать выпуск» → загрузить → опубликовать. Видят только внутренние тестировщики, проверка Google — минуты.
4. Проверить на своём телефоне (обновление приходит через Google Play).
5. Всё хорошо → в выпуске «Продвинуть выпуск» → «Закрытое тестирование» или «Рабочая версия». Файл заново не загружается.
6. В рабочей версии — **поэтапное развёртывание** (например, 10% → 50% → 100%); при ошибках «Остановить развёртывание».
7. По желанию: «Обзор публикации» → **Управляемая публикация** — одобренное выходит только по кнопке «Опубликовать».

Модули (переводы, словари, аудио) приложение берёт с aobible.app: они обновляются у всех сразу после выкладки «в прод», без Play — проверять их на тестовом сайте.

Не ставить `.apk` из папки поверх версии из Play: разные подписи, а удаление Play-версии сотрёт закладки и заметки в приложении.
